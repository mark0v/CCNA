## Summary

Hybrid cloud is not about moving everything to the cloud. It is about deciding what belongs in the cloud, what should stay on-prem, and how to operate both worlds without creating chaos for the engineering team.

Main idea: hybrid cloud is a strategy for placing workloads where they make the most technical and business sense.

## Key Points

- Cloud is rented infrastructure delivered as services.
- On-prem means infrastructure owned and controlled by the organization.
- Cloud is strong for speed, elasticity and managed services.
- On-prem is strong for control, compliance and latency-sensitive workloads.
- Not every workload should move to the cloud.
- Hybrid cloud combines cloud and on-prem environments.
- Operational consistency is a major challenge.
- Cloud-native concepts include containers, Kubernetes and microservices.
- A good hybrid platform reduces tool sprawl.
- Engineers should think of hybrid cloud as an operations decision, not only a vendor decision.

## Notes

### On-Prem vs Cloud

On-prem gives control but requires hardware, space, power, maintenance and upfront cost.

Cloud gives flexibility and fast scaling, but cost, compliance and architecture must be managed carefully.

### Why Not Move Everything?

Some workloads have:

- compliance requirements;
- low-latency needs;
- high storage cost concerns;
- local reliability requirements;
- existing dependencies.

### Make On-Prem More Cloud-Like

One goal of hybrid cloud is to bring modern deployment models such as containers and Kubernetes into private environments while still integrating with public cloud.

## Questions

### Is hybrid cloud just indecision?

No. It is a deliberate choice to place workloads where they fit best.

### What is a major hybrid cloud challenge?

Managing multiple environments consistently without overwhelming the team.
