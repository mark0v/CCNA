## Summary

- STP блокирует лишние Layer 2 пути, чтобы сеть не получила петлю и broadcast storm.
- Это правильное поведение, но оно делает часть физических линков пассивным резервом.
- Если между двумя коммутаторами проложены четыре кабеля, STP может оставить активным только один.
- EtherChannel нужен не вместо STP, а как способ безопасно использовать резервные линки.

## Key Points

- Redundancy без контроля создает Layer 2 loops.
- STP защищает сеть, но не пытается использовать все доступные физические соединения.
- Заблокированный линк полезен для failover, но не помогает обычному трафику до аварии.
- В реальной сети это особенно заметно на uplink-ах между access и distribution switches.
- EtherChannel превращает несколько физических портов в один логический канал, который STP видит как один путь.

## Notes

STP легко любить за то, что он спасает сеть от петель. Если между коммутаторами появляется несколько независимых Layer 2 путей, протокол выбирает безопасную топологию и блокирует лишние порты. Это предотвращает broadcast storm, когда broadcast frames начинают бесконечно ходить по кругу и перегружают весь сегмент.

Но у этого решения есть цена. Физические кабели проложены, порты заняты, оборудование куплено, а часть линков не передает обычный user traffic. Они остаются как backup, но не участвуют в ежедневной передаче данных.

Представим два коммутатора в NetworkChuck Coffee. Между ними подключили четыре линка: хочется и отказоустойчивость, и больше пропускной способности. С точки зрения человека это выглядит логично. С точки зрения STP это четыре потенциальных пути, которые могут создать петлю. Поэтому STP оставляет один forwarding path и блокирует остальные.

Сеть становится безопасной, но неэффективной:

- один активный линк несет POS traffic, камеры, Wi-Fi, voice и back office systems;
- три остальных линка ждут аварии;
- доступная физическая полоса используется не полностью.

Важно не сделать неправильный вывод. STP не "плохой" и не "мешает". Он решает свою задачу: убирает Layer 2 loops. Проблема в том, что redundancy в чистом виде дает нам резерв, но не всегда дает дополнительную рабочую bandwidth.

То, что нам нужно, звучит почти противоречиво: несколько физических линков между одними и теми же коммутаторами должны вести себя как один логический link. Тогда сеть получает и отказоустойчивость, и дополнительную емкость, а STP не видит четыре отдельных redundant paths.

Это и есть причина появления EtherChannel. Он объединяет несколько физических интерфейсов в один logical bundle. Для STP такой bundle выглядит как один интерфейс, поэтому протокол больше не блокирует отдельные кабели как независимые дублирующие пути.

Практический результат:

- больше полезной пропускной способности между коммутаторами;
- сохранение связи при отказе одного физического линка в bundle;
- более аккуратная STP topology;
- меньше wasted bandwidth на важных uplink-ах.

В production-сети EtherChannel особенно полезен между access и distribution switches. Например, если access switch обслуживает точки доступа, POS terminals и камеры, один uplink может стать узким местом. Несколько uplink-ов без EtherChannel STP частично заблокирует. Несколько uplink-ов с EtherChannel смогут работать как один логический канал.

Есть и важное предупреждение: EtherChannel требует строгой согласованности настроек на обеих сторонах. Speed, duplex, trunk/access mode, allowed VLANs, native VLAN и negotiation mode должны совпадать. Если одна сторона настроена иначе, bundle может не подняться или будет вести себя нестабильно.

На этом этапе главное понять не команды, а мотивацию. STP блокирует redundant links ради безопасности. EtherChannel позволяет вернуть эту пропускную способность в работу, не возвращая Layer 2 loop.

## Commands / Terms

| Term | Meaning |
| --- | --- |
| Blocked port | STP-порт, который не пересылает user traffic, чтобы предотвратить петлю. |
| Forwarding path | Активный Layer 2 путь, по которому реально идет трафик. |
| Redundant link | Дополнительное физическое соединение, созданное для отказоустойчивости. |
| Logical link | Канал, который для коммутатора выглядит как один link, даже если внутри несколько физических портов. |
| EtherChannel bundle | Группа физических интерфейсов, объединенных в один логический канал. |
| Wasted bandwidth | Пропускная способность, которая физически доступна, но не используется для обычного трафика. |

## Questions

### 1. Почему STP блокирует часть redundant links?

Answer: Потому что несколько независимых Layer 2 путей между одними и теми же коммутаторами могут создать loop. STP блокирует лишние пути, чтобы предотвратить broadcast storm.

### 2. Почему заблокированный STP-link все равно полезен?

Answer: Он остается резервом. Если активный link упадет, STP может перестроить топологию и использовать резервный путь.

### 3. В чем практическая проблема blocked links?

Answer: Они не передают обычный user traffic. Это означает, что часть купленной и подключенной физической пропускной способности простаивает.

### 4. Как EtherChannel решает эту проблему?

Answer: EtherChannel объединяет несколько физических линков в один logical bundle. STP видит bundle как один link, а трафик может использовать емкость нескольких физических соединений.
