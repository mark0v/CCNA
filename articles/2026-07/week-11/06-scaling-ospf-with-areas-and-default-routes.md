## Summary

- Scaling OSPF начинается с design decisions, а не с одной магической команды.
- Single-area OSPF работает в маленькой сети, но плохо масштабируется при росте topology.
- Multi-area OSPF ограничивает размер LSDB и контролирует, какие details переходят между areas.
- ABR соединяет OSPF areas и может summarize routes.
- ASBR вводит в OSPF routes from outside, например default route к ISP.

## Key Points

- Area 0 - backbone area, к которой подключаются другие OSPF areas.
- OSPF neighbor adjacency требует matching area на link.
- ABR появляется автоматически, когда router имеет OSPF interfaces в more than one area.
- Type 3 LSA создается ABR для inter-area route information.
- `default-information originate` injects default route into OSPF as external route.
- DR/BDR elects per broadcast segment, not once for the whole OSPF domain.

## Notes

Scaling OSPF начинается не с syntax, а с business design. Если у NetworkChuck Coffee появляются десятки или сотни cafes, нет смысла ставить отдельный internet circuit в каждом location. Логичнее централизовать shared services и internet access в более крупной site, например fallout shelter, куда branch cafes уже routed.

Практический change:

- internet connection moved to fallout shelter;
- fallout shelter router получает WAN interface к ISP;
- на fallout shelter router добавляется default route к ISP;
- cafe routers позже получают default route through OSPF, а не через manual static config.

NAT может быть отдельным future step. Для routing design сначала важно, что fallout shelter знает path to internet.

## Why One Big OSPF Area Hurts

Single-area OSPF обычно начинается с Area 0. Для CCNA foundation это нормально. Но в большой сети one giant area становится проблемой.

OSPF - link-state protocol. Routers внутри area строят common LSDB, link-state database. Это topology map area. Чем больше area, тем больше map:

- больше LSAs;
- больше SPF recalculations;
- больше flooding при changes;
- больше CPU and memory usage;
- больше шум от flapping interfaces.

Если один unstable link flaps внутри large area, routers в этой area должны process updates. В маленькой topology это почти незаметно. В большой business network это становится design problem.

## Multi-Area OSPF

Multi-area OSPF разбивает topology на logical chunks:

- Area 0 остается backbone.
- Cafe можно перенести в Area 1.
- Fallout shelter router становится boundary между Area 0 and Area 1.

Важно: OSPF neighbors on same link должны быть в same area. Если одна сторона WAN link в Area 0, а другая в Area 1, adjacency не сформируется. Это expected behavior, а не bug.

Пример mistake:

```text
FalloutShelter(config-router)# network 172.16.0.2 0.0.0.0 area 1
Cafe(config-router)# network 172.16.0.1 0.0.0.0 area 0
```

Area mismatch breaks neighbor relationship. Исправление: обе стороны WAN segment должны use same area.

Когда fallout shelter router имеет interfaces in Area 0 and Area 1, он становится ABR.

## ABR And Route Summarization

ABR, Area Border Router, соединяет OSPF areas. Он может advertise routes between areas и summarize them.

ABR role появляется автоматически. Нет команды "become ABR". Если router участвует в more than one OSPF area, OSPF recognizes it as ABR.

Route summarization нужен, чтобы не передавать все small routes между areas. Если subnets contiguous, их можно collapse into summary route.

Пример:

```text
router ospf 1
 area 0 range 10.10.0.0 255.255.0.0
```

До summarization cafe router может видеть multiple inter-area routes. После summarization он видит одну larger route. Это дает:

- smaller routing table;
- fewer details crossing area boundary;
- less churn;
- cleaner design;
- better scalability.

Address planning matters. Если branch subnets scattered randomly, summarization становится painful or impossible. Если заранее держать IP blocks contiguous, OSPF design later becomes much cleaner.

## LSA Types To Know

OSPF describes topology and routes using LSAs, link-state advertisements.

Important LSA types:

| LSA Type | Generated by | Meaning |
| --- | --- | --- |
| Type 1 | Every OSPF router | Router LSA for its own links inside area. |
| Type 2 | DR | Network LSA for broadcast segment. |
| Type 3 | ABR | Summary LSA for inter-area routes. |
| Type 5 | ASBR | External LSA for routes from outside OSPF. |

For real troubleshooting, you may not recite LSA numbers every day. For CCNA-style understanding, they matter because they explain who is injecting which information.

## ASBR And Default Route Injection

ASBR, Autonomous System Boundary Router, connects OSPF to something outside OSPF. If fallout shelter router has ISP connection and static default route, it can become ASBR when it injects that external route into OSPF.

Default route:

```text
ip route 0.0.0.0 0.0.0.0 <ISP-next-hop>
```

Inject into OSPF:

```text
router ospf 1
 default-information originate
```

Result: cafe routers learn gateway of last resort through OSPF. Without this, every cafe router might need manual static default route. With hundreds of cafes, that manual model does not scale.

The default route appears as external OSPF route, often `O*E2` in routing table. In LSDB, external routes are represented by Type 5 LSAs from ASBR.

ABR and ASBR roles can exist on the same router. In this design, fallout shelter router is:

- ABR because it connects Area 0 and Area 1;
- ASBR because it injects outside/default route into OSPF.

## DR And BDR Per Segment

DR/BDR election happens per broadcast segment, not once per OSPF domain.

That means:

- VLAN 10 can have one DR/BDR pair;
- VLAN 20 can have another;
- a point-to-point WAN link has no DR/BDR election;
- different broadcast segments elect independently.

By default, higher router ID often wins if priority ties. You can influence election with interface OSPF priority:

```text
interface g0/0
 ip ospf priority 100
```

In larger designs, do not let DR/BDR happen accidentally. A stronger, more central router is often a better DR than a small edge router.

## Commands / Terms

| Command / Term | Meaning |
| --- | --- |
| Area 0 | OSPF backbone area. |
| ABR | Area Border Router, connected to more than one OSPF area. |
| ASBR | Autonomous System Boundary Router, injects external routes into OSPF. |
| `area 0 range ...` | Summarizes routes from an area on ABR. |
| `default-information originate` | Advertises default route into OSPF. |
| Type 3 LSA | Summary LSA generated by ABR. |
| Type 5 LSA | External LSA generated by ASBR. |
| DR/BDR | Designated and backup designated routers per broadcast segment. |

## Questions

### 1. Почему one giant OSPF area плохо масштабируется?

Answer: Все routers в area share LSDB. Чем больше area, тем больше updates, SPF recalculations, CPU/memory usage и noise при changes.

### 2. Что делает ABR?

Answer: ABR соединяет OSPF areas, передает route information между ними и может summarize routes.

### 3. Почему OSPF neighbor ломается при area mismatch?

Answer: Interfaces on the same link должны находиться в same OSPF area. Если area IDs отличаются, adjacency не формируется.

### 4. Что делает `default-information originate`?

Answer: It injects default route into OSPF, чтобы other routers learned gateway of last resort dynamically.

### 5. DR/BDR выбираются один раз на весь OSPF domain?

Answer: Нет. DR/BDR election happens per broadcast segment. Point-to-point links do not use DR/BDR election.
