## Кратко

- Перед приоритизацией трафик нужно определить.
- `Classification` отвечает на вопрос: что это за трафик?
- `Marking` отвечает на вопрос: какую метку дать этому трафику?
- Классифицировать можно по IP-адресам, портам, протоколам, интерфейсам, VLAN или приложению.
- `ACL`, `NBAR` и `class map` помогают группировать трафик для политики `QoS`.
- На Layer 2 используется `CoS`.
- На Layer 3 чаще используется `DSCP`.
- Для голосового трафика особенно важно помнить `EF`, или `Expedited Forwarding`.

## Главное

- `QoS` начинается не с очередей, а с понимания трафика.
- Классификация - это проверка пакета и отнесение его к категории.
- Маркировка - это метка, которую другие устройства могут использовать дальше по пути.
- Метка экономит ресурсы: не каждое устройство должно заново глубоко анализировать пакет.
- Классифицировать трафик лучше как можно ближе к краю сети.
- `CoS` использует 3 бита в 802.1Q tag и дает значения от 0 до 7.
- `DSCP` использует 6 бит и дает более гибкую систему маркировки.

## Заметки

Многие хотят сразу перейти к самой заметной части `QoS`:

```text
Сделать голос первым.
Дать видео приоритет.
Ограничить плохой трафик.
```

Но перед этим нужно ответить на базовый вопрос:

```text
Что это за трафик?
```

Нельзя правильно приоритизировать поток, если сеть не понимает, что перед ней.

Именно поэтому основа `QoS` - классификация и маркировка.

## Что такое классификация

Классификация - это процесс определения типа трафика.

Устройство смотрит на пакет и решает:

- это голос;
- это web;
- это видео;
- это гостевая сеть;
- это платежная система;
- это резервное копирование;
- это трафик управления.

После этого трафик можно обработать по-разному.

Простая мысль:

```text
Сначала определить. Потом управлять.
```

## По чему можно классифицировать

Трафик можно определять по разным признакам:

- source IP;
- destination IP;
- протокол;
- TCP или UDP port;
- интерфейс;
- VLAN;
- приложение;
- время;
- уже существующая метка.

Чем точнее классификация, тем аккуратнее политика `QoS`.

Но точность стоит ресурсов. Глубокая проверка приложений тяжелее, чем простое совпадение по адресу или порту.

## Списки ACL как способ классификации

Один из привычных способов классифицировать трафик - использовать `ACL`.

`ACL` может сопоставлять:

- source address;
- destination address;
- протокол;
- port number;
- иногда time range.

Например, можно выделить трафик платежной системы или отделить гостевую сеть от офисной.

В `QoS` `ACL` часто не используется для блокировки. Он используется как способ сказать:

```text
Вот этот трафик относится к нужной категории.
```

Это важное отличие от привычного применения access lists в фильтрации.

## Распознавание приложений через NBAR

`NBAR`, или `Network Based Application Recognition`, позволяет устройству распознавать приложения глубже, чем простой port number.

Это полезно, потому что современные приложения не всегда ведут себя предсказуемо:

- могут использовать разные порты;
- могут маскироваться под обычный web traffic;
- могут менять поведение;
- могут требовать более точного распознавания.

`NBAR` дает более умную классификацию, но требует больше ресурсов устройства.

Практический вывод:

```text
Используй глубокое распознавание там, где оно действительно нужно.
```

## Карта классов

`Class map` - это место, где группируются условия совпадения.

Упрощенно:

```text
Все, что совпало с этими правилами, попадает в этот класс.
```

Например:

- voice traffic;
- video traffic;
- business-critical traffic;
- guest traffic;
- scavenger traffic.

`Class map` помогает не держать все правила в голове. Она создает аккуратные "корзины" для трафика, с которыми потом работает политика.

## Что такое маркировка

После классификации трафик можно маркировать.

Маркировка - это назначение значения, которое сообщает другим устройствам:

```text
Как к этому трафику относиться?
```

Если классификация - это расследование, то маркировка - это наклейка на коробке.

Устройство один раз разобралось, что внутри. Затем поставило метку. Дальше другие устройства могут быстро принять решение по метке, не выполняя всю работу заново.

## Почему маркировка важна

Маркировка делает `QoS` масштабируемым.

Без маркировки каждое устройство по пути должно заново анализировать трафик:

- что это за приложение;
- откуда оно пришло;
- куда идет;
- какой порт использует;
- насколько оно важно.

С маркировкой устройство может просто посмотреть на значение `CoS` или `DSCP`.

Это особенно важно в больших сетях, где одни и те же потоки проходят через много устройств.

## Маркировка CoS на втором уровне

`CoS`, или `Class of Service`, - это маркировка на Layer 2.

Она хранится в 802.1Q VLAN tag.

Важные факты:

- используется 3 бита;
- доступно 8 значений: от 0 до 7;
- особенно важна на trunk links;
- работает там, где есть VLAN tag.

Примерная логика:

```text
Низкие значения - менее важный трафик.
Высокие значения - более важный трафик.
```

Но самый верх не всегда для пользовательского трафика. Network control traffic часто важнее голоса, потому что без управления сеть сама может развалиться.

## Маркировка IP Precedence и DSCP

Старая маркировка Layer 3 называлась `IP Precedence`.

Она тоже использовала 3 бита. Это давало ограниченное количество уровней.

Позже появился `DSCP`, или `Differentiated Services Code Point`.

`DSCP` использует 6 бит и дает до 64 значений.

Это намного гибче, потому что современные сети обслуживают больше типов приложений и требуют более точных политик.

## Как читать AF

В `DSCP` часто встречаются значения `AF`, или `Assured Forwarding`.

Примеры:

```text
AF11
AF12
AF13
AF23
```

В `AFxy`:

- первая цифра - traffic class;
- вторая цифра - drop preference.

Для traffic class:

```text
Выше число - лучше класс.
```

Для drop preference:

```text
Ниже число - меньше вероятность отбрасывания.
```

Пример:

```text
AF11 лучше AF12 внутри одного класса.
AF12 лучше AF13 внутри одного класса.
AF23 выше по классу, чем AF11.
```

Сначала важен класс. Потом - вероятность отбрасывания внутри класса.

## Метка EF для голоса

Самая важная метка для запоминания на этом уровне - `EF`.

`EF` означает `Expedited Forwarding`.

Обычно она используется для voice traffic.

Причина простая: голос очень чувствителен к задержке, jitter и потерям. Ему нужно быстрое и предсказуемое обслуживание.

Если нужно запомнить одну `DSCP` метку для `CCNA`, начни с `EF`.

## Сценарий NetworkChuck Coffee

В NetworkChuck Coffee по сети одновременно идут:

- VoIP;
- платежи;
- камеры;
- гостевой Wi-Fi;
- back-office трафик;
- web browsing;
- обновления.

Если все это выглядит одинаково для сети, `QoS` не сможет принять хорошее решение.

Нужно:

1. Классифицировать голос.
2. Классифицировать платежи.
3. Отделить guest traffic.
4. Пометить важные потоки.
5. Дать downstream devices возможность доверять этим меткам.

Так сеть начинает понимать, что важнее.

## Практический совет

Классифицируй трафик как можно ближе к edge.

Причина:

- там легче понять источник трафика;
- там проще отделить user traffic от network traffic;
- глубокая проверка не повторяется на каждом устройстве;
- дальше по сети можно использовать метки.

Хорошая схема:

```text
Classify once.
Mark once.
Trust and enforce downstream.
```

## Главный вывод

`QoS` начинается с классификации и маркировки.

Классификация определяет, что это за трафик. Маркировка дает ему метку, чтобы другие устройства могли быстро принимать решения.

На Layer 2 используется `CoS`. На Layer 3 чаще используется `DSCP`. Для голоса важно помнить `EF`.

Без классификации и маркировки дальнейшие механизмы `QoS` - очереди, shaping, policing и приоритеты - не имеют нормальной основы.

## Команды и термины

| Термин | Значение |
| --- | --- |
| classification | Определение типа трафика. |
| marking | Назначение метки трафику. |
| `ACL` | Access Control List, может использоваться для совпадения трафика в `QoS`. |
| `NBAR` | Network Based Application Recognition, распознавание приложений. |
| `class map` | Группа условий совпадения для класса трафика. |
| `CoS` | Class of Service, маркировка Layer 2 в 802.1Q tag. |
| `IP Precedence` | Старая 3-битная маркировка Layer 3. |
| `DSCP` | Differentiated Services Code Point, 6-битная маркировка Layer 3. |
| `AF` | Assured Forwarding, группа значений `DSCP`. |
| `EF` | Expedited Forwarding, значение `DSCP`, обычно для voice traffic. |
| drop preference | Вероятность отбрасывания внутри класса. |

## Вопросы

### 1. Что такое классификация в QoS?

Ответ: Определение типа трафика перед применением политики.

### 2. Что такое маркировка?

Ответ: Назначение трафику метки, чтобы другие устройства могли быстрее принять решение.

### 3. Чем CoS отличается от DSCP?

Ответ: `CoS` работает на Layer 2 в 802.1Q tag, а `DSCP` работает на Layer 3 в IP header.

### 4. Зачем нужен NBAR?

Ответ: Для более точного распознавания приложений, когда портов и адресов недостаточно.

### 5. Какую DSCP метку важно помнить для голоса?

Ответ: `EF`, или `Expedited Forwarding`.
