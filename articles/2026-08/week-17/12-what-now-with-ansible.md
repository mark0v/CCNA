## Кратко

- После знакомства с Ansible важно не просто понять идею, а потрогать tool руками.
- Начинать можно с маленькой lab: Raspberry Pi, Linux server или VM.
- Для первого опыта не нужен большой парк Cisco devices.
- Один router или switch уже достаточно, чтобы понять workflow.
- Playbook - это файл с automation instructions для Ansible.
- Хорошие первые задачи: создать файлы, сделать config backup, проверить состояние, применить простую настройку.
- Lab-проект можно описать в resume и использовать как предметный разговор на interview.
- Цель - превратить знание в практический skill.

## Главное

- Ansible нельзя выучить только просмотром урока.
- Маленькая lab лучше, чем ожидание "идеальной" enterprise-среды.
- Практика дает muscle memory: install, connect, run, break, fix, repeat.
- Home lab показывает initiative и реальный интерес.
- Для NetworkChuck Coffee Ansible может начинаться с простых задач: backup configs, стандартные settings, небольшие changes.

## Заметки

Самая плохая идея после урока про Ansible - сказать:

```text
Круто, я понял.
```

И больше никогда его не открыть.

Ansible выглядит понятным, когда смотришь демонстрацию. Но настоящий прогресс начинается, когда ты ставишь его сам, запускаешь playbook, получаешь ошибку, исправляешь ее и запускаешь снова.

## Начни с малого

Не нужен огромный enterprise lab.

Для старта подойдет:

- Raspberry Pi;
- Linux server;
- маленькая VM;
- старый laptop с Linux;
- cloud VM.

Эта машина станет Ansible box - местом, откуда Ansible запускает automation tasks.

Главная задача первой lab - не впечатлить кого-то масштабом. Главная задача - сделать что-то реальное.

## Что можно сделать первым

Первые tasks должны быть простыми и безопасными:

- создать пару files;
- скопировать небольшой config;
- проверить доступность device;
- собрать hostname;
- собрать interface status;
- сделать backup running configuration;
- применить настройку в lab;
- сохранить output.

Это не выглядит грандиозно, но именно так появляется практическое понимание.

Ты видишь:

- как Ansible подключается;
- где лежит inventory;
- как выглядит playbook;
- какие ошибки появляются;
- как читать результат;
- что нужно исправлять.

## Не нужна гора оборудования

Для начала не нужны десятки Cisco devices.

Один router или один switch уже дает полезный опыт.

Сценарий простой:

```text
Написать playbook.
Подключиться к device.
Выполнить task.
Посмотреть result.
Исправить mistakes.
Повторить.
```

Именно здесь теория становится практикой.

Не нужно ждать, пока появится идеальный lab. Идеальная lab часто становится оправданием, чтобы ничего не делать.

## Что такое playbook на практике

`Playbook` - это набор инструкций для Ansible.

Он может описывать:

- какие devices использовать;
- какие credentials нужны;
- какие variables подставить;
- какие tasks выполнить;
- какой result ожидать.

Например:

```text
Подключиться к cafe-switch-01.
Проверить текущий hostname.
Собрать interface status.
Сохранить output в файл.
```

Это уже automation.

Не потому что задача сложная, а потому что она повторяемая.

## Почему это полезно для карьеры

Фраза "я изучал Ansible" звучит слабо.

Фраза "я поставил Ansible в lab, написал playbooks и автоматизировал несколько задач" звучит совсем иначе.

Даже маленький home lab показывает:

- initiative;
- curiosity;
- готовность учиться руками;
- понимание real workflow;
- способность разбирать ошибки.

На interview это дает конкретные темы для разговора.

Ты можешь объяснить:

- что построил;
- как подключался;
- какие playbooks написал;
- что сломалось;
- как исправил;
- что бы улучшил дальше.

## Практический совет

Не жди, пока job потребует Ansible.

Собери маленькую lab сейчас и документируй процесс.

Сохраняй:

- screenshots;
- playbooks;
- inventory files;
- notes по ошибкам;
- команды проверки;
- before/after examples.

Это полезно и для interview, и для самого себя.

Документация доказывает, что ты не просто "посмотрел тему", а действительно сделал работу.

## Пример NetworkChuck Coffee

Представим маленький старт:

```text
Один router в back office.
Один switch для cafe floor.
Одна Linux VM как Ansible box.
```

Что можно автоматизировать:

- backup configs;
- проверку interface status;
- стандартные SSH settings;
- одинаковые banners;
- простую VLAN configuration в lab;
- сбор facts;
- проверку reachability.

Потом сеть растет.

Одна кофейня становится тремя. Потом десятью.

Теперь одинаковые policies, management settings и access rules нужно применять везде одинаково.

Вот здесь Ansible перестает быть просто интересным tool и становится способом не утонуть в ручной работе.

## Добавь Ansible в toolbox

Ansible стоит воспринимать как реальный инструмент, а не как trivia.

Не нужно сразу становиться expert.

Нужно пройти базовый цикл:

```text
Install.
Connect.
Run.
Break.
Fix.
Repeat.
```

После нескольких таких циклов уверенность растет быстрее, чем после пассивного просмотра уроков.

## Главный вывод

Что делать после знакомства с Ansible?

Строить.

Экспериментировать.

Запустить маленькую lab.

Написать простой playbook.

Подключиться хотя бы к одному device.

Сломать что-нибудь в безопасной среде и разобраться, почему оно сломалось.

Так Ansible превращается из информации в skill.

## Команды и термины

| Термин | Значение |
| --- | --- |
| `Ansible` | Agentless automation tool, часто используемый в networking. |

| lab | Безопасная среда для практики. |
| `playbook` | Файл с instructions для Ansible. |

## Вопросы

### 1. Почему нельзя останавливаться на теории Ansible?

Ответ: Потому что реальное понимание появляется через установку, запуск, ошибки и исправления.

### 2. Что можно использовать как Ansible box?

Ответ: Raspberry Pi, Linux server, VM, старый laptop с Linux или cloud VM.

### 3. Нужно ли много Cisco devices для старта?

Ответ: Нет. Один router или switch уже достаточно для первых практических шагов.

### 4. Что такое playbook?

Ответ: Набор instructions, которые Ansible выполняет повторяемо.

### 5. Какие задачи хороши для первой lab?

Ответ: Config backup, сбор interface status, проверка reachability, создание файлов и простые lab changes.

### 6. Почему home lab полезен для interview?

Ответ: Он дает конкретный опыт, который можно объяснить: что построил, что сломалось и как исправил.
