## Кратко

Dynamic NAT позволяет группе внутренних узлов временно получать адреса из пула публичных IPv4-адресов. В отличие от static NAT, администратору не нужно заранее создавать постоянное соответствие для каждого клиента. Маршрутизатор выбирает свободный адрес из пула при появлении трафика и создаёт динамическую запись трансляции.

Для настройки нужны четыре элемента:

1. Интерфейсы с ролями `ip nat inside` и `ip nat outside`.
2. ACL, определяющий внутренние адреса для трансляции.
3. Пул доступных inside global адресов.
4. Команда, связывающая ACL с NAT pool.

Dynamic NAT гибче static NAT, но не решает проблему дефицита публичных адресов. Каждому одновременно активному внутреннему узлу всё ещё требуется отдельный адрес из пула. Для обычного доступа множества клиентов в интернет чаще применяется PAT, или NAT overload.

## Ключевые идеи

- Static NAT создаёт постоянное соответствие one-to-one.
- Dynamic NAT выдаёт внутренним узлам свободные адреса из публичного пула.
- Каждая активная dynamic NAT translation остаётся one-to-one.
- Standard ACL определяет, какие source addresses разрешено переводить.
- ACL сама по себе ничего не фильтрует, пока не применена к функции или интерфейсу.
- Wildcard mask `0.0.0.255` соответствует сети `/24`.
- NAT pool задаёт первый адрес, последний адрес и маску сети.
- Команда `ip nat inside source list ... pool ...` связывает внутреннюю группу с публичным пулом.
- Несколько маршрутизируемых внутренних сегментов могут использовать один outside interface.
- При исчерпании пула новые клиенты не получают трансляцию.
- Dynamic NAT требует корректной маршрутизации публичного диапазона со стороны провайдера.
- Для массового клиентского доступа PAT обычно практичнее.

## От static NAT к dynamic NAT

Static NAT выглядит так:

```text
192.168.10.10 <-> 216.0.5.50
192.168.10.11 <-> 216.0.5.51
192.168.10.12 <-> 216.0.5.52
```

Каждое соответствие настраивается вручную и существует постоянно. Такой подход полезен для серверов, которым нужен предсказуемый публичный адрес, но плохо подходит для клиентской сети с DHCP.

Dynamic NAT описывает две группы:

```text
Inside group: 192.168.10.0/24
Public pool:  216.0.5.50-216.0.5.100
```

При появлении исходящего трафика маршрутизатор временно связывает конкретный внутренний адрес со свободным адресом из пула:

```text
192.168.10.21 <-> 216.0.5.50
192.168.10.38 <-> 216.0.5.51
192.168.10.74 <-> 216.0.5.52
```

Администратор не определяет заранее, какой клиент получит какой публичный адрес.

## Почему Dynamic NAT называют many-to-many

Dynamic NAT связывает множество возможных внутренних адресов с множеством публичных адресов. Однако каждая активная запись остаётся отдельным соответствием one-to-one:

```text
one active inside local <-> one inside global
```

Один публичный адрес из обычного dynamic NAT pool нельзя одновременно выдать нескольким внутренним клиентам. Совместное использование одного адреса появляется при PAT.

## Шаг 1. Назначить роли интерфейсов

Маршрутизатор должен понимать, с какой стороны находятся внутренние адреса и через какую сторону трафик уходит наружу.

Интерфейс к сети кафе:

```cisco
interface GigabitEthernet0/0
 description Cafe LAN
 ip nat inside
```

Интерфейс к провайдеру:

```cisco
interface GigabitEthernet0/2
 description ISP uplink
 ip nat outside
```

Если у маршрутизатора есть ещё один маршрутизируемый внутренний сегмент, он также может участвовать в NAT:

```cisco
interface GigabitEthernet0/1
 description Fallout Shelter LAN
 ip nat inside
```

Одного `ip nat inside` недостаточно: сеть этого интерфейса также должна соответствовать ACL, используемому правилом NAT.

## Шаг 2. Определить внутренние адреса с помощью ACL

Для сети кафе:

```text
192.168.10.0/24
```

можно создать standard numbered ACL:

```cisco
access-list 1 permit 192.168.10.0 0.0.0.255
```

Эта запись означает:

```text
Совпадают все source addresses от 192.168.10.0 до 192.168.10.255.
```

В контексте NAT слово `permit` означает, что совпавший source address разрешено обрабатывать правилом трансляции. Это не означает автоматическое разрешение трафика через firewall.

### ACL как классификатор

ACL часто ассоциируют только с безопасностью, но её базовая задача состоит в сопоставлении трафика с условиями.

ACL может применяться к:

- фильтрации пакетов на интерфейсе;
- NAT;
- policy-based routing;
- QoS;
- route filtering;
- другим функциям IOS.

Пока список ни к чему не привязан, он лишь хранит условия сопоставления.

## Wildcard mask

Wildcard mask указывает, какие биты адреса должны совпасть.

Правило:

```text
0 = соответствующий бит должен совпасть
1 = соответствующий бит можно игнорировать
```

Для `/24`:

```text
Subnet mask:   255.255.255.0
Wildcard mask:   0.0.0.255
```

Поэтому:

```cisco
access-list 1 permit 192.168.10.0 0.0.0.255
```

фиксирует первые три октета и допускает любое значение последнего октета.

Практический способ вычисления:

```text
255.255.255.255
- subnet mask
= wildcard mask
```

### Добавление второй внутренней сети

Если дополнительная сеть имеет адрес:

```text
192.168.20.0/24
```

её можно добавить в тот же ACL:

```cisco
access-list 1 permit 192.168.20.0 0.0.0.255
```

Проверка:

```cisco
show access-lists 1
```

Современный IOS покажет записи с sequence numbers, даже если ACL создавался старой numbered syntax.

## Шаг 3. Создать публичный NAT pool

В лаборатории используется диапазон:

```text
216.0.5.50-216.0.5.100
```

Пул создаётся командой:

```cisco
ip nat pool cafepublic 216.0.5.50 216.0.5.100 netmask 255.255.255.0
```

Чтение команды:

```text
Создать NAT pool с именем cafepublic,
начиная с 216.0.5.50,
заканчивая 216.0.5.100,
с маской 255.255.255.0.
```

Имя `cafepublic` локально значимо только для конфигурации маршрутизатора.

### Размер пула

Количество адресов считается включительно:

```text
100 - 50 + 1 = 51
```

Следовательно, пул содержит 51 inside global address.

Это не значит, что любой произвольный диапазон можно использовать как публичный. Провайдер должен выделить его организации и маршрутизировать к NAT router.

## Шаг 4. Связать ACL с пулом

Команда dynamic NAT:

```cisco
ip nat inside source list 1 pool cafepublic
```

Её можно прочитать как предложение:

```text
Для inside source addresses, совпавших с ACL 1,
использовать addresses из pool cafepublic.
```

Теперь правило содержит:

- классификацию внутренних source addresses;
- диапазон доступных inside global addresses;
- направление NAT благодаря interface roles.

## Полная конфигурация

```cisco
enable
configure terminal

interface GigabitEthernet0/0
 description Cafe LAN
 ip nat inside

interface GigabitEthernet0/1
 description Fallout Shelter LAN
 ip nat inside

interface GigabitEthernet0/2
 description ISP uplink
 ip nat outside

access-list 1 permit 192.168.10.0 0.0.0.255
access-list 1 permit 192.168.20.0 0.0.0.255

ip nat pool cafepublic 216.0.5.50 216.0.5.100 netmask 255.255.255.0
ip nat inside source list 1 pool cafepublic

end
```

Названия интерфейсов, внутренние сети и публичный диапазон необходимо адаптировать к реальной topology.

## Что происходит при передаче трафика

Пусть клиент:

```text
192.168.10.21
```

отправляет трафик в интернет.

Маршрутизатор:

1. Получает пакет на interface с `ip nat inside`.
2. Проверяет source address по ACL 1.
3. Находит свободный address в pool `cafepublic`.
4. Создаёт translation, например:

```text
192.168.10.21 <-> 216.0.5.50
```

5. Отправляет изменённый пакет через interface с `ip nat outside`.
6. Использует запись для обратного трафика.

Следующий внутренний клиент получает следующий доступный адрес или другой свободный адрес из пула.

## Проверка

Посмотреть записи NAT:

```cisco
show ip nat translations
```

Пример:

```text
Pro  Inside global  Inside local     Outside local  Outside global
---  216.0.5.50     192.168.10.21    ---            ---
---  216.0.5.51     192.168.20.15    ---            ---
```

Посмотреть статистику и параметры:

```cisco
show ip nat statistics
```

Проверить ACL:

```cisco
show access-lists 1
```

Проверить конфигурацию:

```cisco
show running-config | include ip nat
show running-config | include access-list
show ip interface brief
show ip route
```

Для создания записей нужно сгенерировать трафик от подходящего внутреннего клиента к доступному outside host.

## Главный предел: исчерпание пула

Пул из 51 адреса одновременно обслуживает не более 51 active one-to-one translations.

Когда все адреса заняты:

```text
Client 1  -> public address 1
Client 2  -> public address 2
...
Client 51 -> public address 51
Client 52 -> no available public address
```

ACL может совпасть, routing может быть корректным, а интерфейсы могут иметь правильные роли, но 52-й клиент не получит доступ через это правило до освобождения адреса.

Именно поэтому dynamic NAT не является обычным конечным решением для большого числа пользовательских устройств.

## Dynamic NAT и PAT

| Свойство | Dynamic NAT | PAT / NAT overload |
| --- | --- | --- |
| Public addresses | Пул адресов | Один или несколько адресов |
| Active mapping | Один public IP на один inside host | Один public IP для множества sessions |
| Разделение | По IP address | По protocol и port/identifier |
| Масштабируемость | Ограничена размером пула | Значительно выше |
| Типичное применение | Специальные требования к пулу | Общий internet access |

Dynamic NAT полезен, когда:

- организация действительно располагает публичным пулом;
- каждому активному узлу нужен отдельный публичный source address;
- соответствие может быть временным;
- число одновременных узлов не превышает размер пула.

PAT практичнее, когда множество клиентов должно совместно использовать один или несколько публичных адресов.

## Маршрутизация публичного пула

NAT не создаёт маршруты автоматически во всей внешней сети.

Провайдер должен доставлять трафик для:

```text
216.0.5.50-216.0.5.100
```

к edge router. Это может обеспечиваться connected subnet, provider route или выделенным routed block.

Также маршрутизатору нужны:

- route к outside destinations;
- route к внутренним сетям;
- корректные default gateways на клиентах;
- обратный путь для ответов.

## Очистка динамических записей

В лаборатории:

```cisco
clear ip nat translation *
```

Команда удаляет текущие dynamic translations. В production она может оборвать активные соединения, поэтому её нельзя использовать без оценки влияния.

Удаление самой конфигурации выполняется отдельно:

```cisco
no ip nat inside source list 1 pool cafepublic
no ip nat pool cafepublic
no access-list 1
```

Сначала следует удалить правило, которое ссылается на pool и ACL.

## Порядок диагностики

Если dynamic NAT не работает:

1. Проверить IP address, mask и default gateway клиента.
2. Проверить routing без предположения, что NAT исправит маршруты.
3. Проверить `ip nat inside` на входящем interface.
4. Проверить `ip nat outside` на внешнем interface.
5. Проверить, совпадает ли source address с ACL.
6. Проверить hit counters командой `show access-lists`.
7. Проверить имя и диапазон NAT pool.
8. Проверить связь ACL и pool в NAT rule.
9. Проверить наличие свободных адресов в пуле.
10. Проверить маршрутизацию публичного пула со стороны ISP.
11. Проверить ACL/firewall policies.
12. Проверить `show ip nat translations` и `show ip nat statistics`.

## Частые ошибки

### ACL создан, но не связан с NAT

Список не выполняет действие самостоятельно. Нужна команда:

```cisco
ip nat inside source list 1 pool cafepublic
```

### Перепутана wildcard mask

Для `/24` используется:

```text
0.0.0.255
```

а не subnet mask `255.255.255.0`.

### Дополнительный интерфейс отмечен как inside, но сеть не добавлена в ACL

Interface role определяет сторону NAT, но не включает source network в правило автоматически.

### Пул считается без последнего адреса

Границы включаются. Диапазон `.50-.100` содержит 51 адрес.

### Ожидается совместное использование одного адреса

Обычный dynamic NAT не выполняет overload. Для этого нужен PAT.

### Используется произвольный публичный диапазон

Inside global addresses должны быть выделены и маршрутизироваться к организации.

## Контрольные вопросы

### Вопрос 1

Чем dynamic NAT отличается от static NAT?

Ответ:

```text
Dynamic NAT временно выбирает свободный inside global address из пула,
а static NAT использует заранее настроенное постоянное соответствие.
```

### Вопрос 2

Что делает ACL в этой конфигурации?

Ответ:

```text
Определяет source addresses, к которым применяется dynamic NAT.
```

### Вопрос 3

Сколько адресов находится в диапазоне `.50-.100`?

Ответ:

```text
51 адрес: 100 - 50 + 1.
```

### Вопрос 4

Что произойдёт с 52-м одновременно активным клиентом?

Ответ:

```text
Он не получит translation, пока в пуле не освободится public address.
```

### Вопрос 5

Почему PAT чаще используется для общего доступа в интернет?

Ответ:

```text
PAT позволяет множеству клиентов одновременно использовать один
или несколько public addresses, различая sessions по transport information.
```

## Команды и термины

| Команда / термин | Назначение |
| --- | --- |
| Dynamic NAT | Временная выдача адреса из публичного пула. |
| NAT pool | Диапазон inside global addresses. |
| Standard ACL | Сопоставляет source IPv4 addresses. |
| Wildcard mask | Определяет значимые и игнорируемые биты адреса. |
| `ip nat inside` | Обозначает внутреннюю сторону NAT. |
| `ip nat outside` | Обозначает внешнюю сторону NAT. |
| `access-list 1 permit ...` | Определяет внутренние source addresses. |
| `ip nat pool ...` | Создаёт пул адресов. |
| `ip nat inside source list 1 pool cafepublic` | Связывает ACL с pool. |
| `show ip nat translations` | Показывает активные mappings. |
| `show ip nat statistics` | Показывает NAT configuration и counters. |
| `show access-lists` | Показывает ACL entries и match counters. |
