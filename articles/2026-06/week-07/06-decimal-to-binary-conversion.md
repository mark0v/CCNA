## Кратко

Для IPv4 subnetting необходимо уверенно переводить десятичные числа от `0` до `255` в восьмибитное двоичное представление.

Каждая позиция в IPv4 octet имеет фиксированный вес:

```text
128  64  32  16   8   4   2   1
```

Если значение позиции используется, записывается `1`. Если не используется, записывается `0`.

Например:

```text
153 = 128 + 16 + 8 + 1
153 = 10011001
```

Это не отдельный математический трюк. Binary помогает увидеть, какие bits принадлежат network portion, какие host portion и где проходят subnet boundaries.

## Ключевые идеи

- Bit принимает только одно из двух значений: `0` или `1`.
- Byte состоит из 8 bits.
- IPv4 address состоит из 4 octets, то есть из 32 bits.
- Один octet хранит значение от `0` до `255`.
- Веса восьми позиций: `128`, `64`, `32`, `16`, `8`, `4`, `2`, `1`.
- `1` означает, что вес позиции входит в сумму.
- `0` означает, что вес позиции не используется.
- Binary octet всегда полезно записывать всеми восемью bits, включая leading zeros.
- Decimal-to-binary conversion используется при изучении subnet masks, prefixes, network addresses и broadcast addresses.

## Зачем Network Engineer Нужен Binary

IPv4 address обычно записывается в удобной для человека dotted-decimal notation:

```text
192.168.1.10
```

Но каждый decimal octet представляет 8 bits:

```text
192      168      1        10
11000000 10101000 00000001 00001010
```

Subnet mask также является 32-bit value:

```text
255.255.255.0
11111111.11111111.11111111.00000000
```

В binary хорошо видно, где заканчивается network portion и начинается host portion. Поэтому понимание bits делает subnetting предсказуемым, а не основанным на запоминании отдельных таблиц.

## Bit, Byte и Octet

### Bit

Bit является минимальной единицей двоичных данных:

```text
0
```

или:

```text
1
```

### Byte

Byte состоит из 8 bits:

```text
00000000
```

### Octet

В контексте IPv4 группу из 8 bits обычно называют octet.

```text
1 octet = 8 bits
4 octets = 32 bits
```

Пример:

```text
IPv4: 172.16.5.25

Octet 1: 172
Octet 2: 16
Octet 3: 5
Octet 4: 25
```

Каждый octet переводится в binary независимо от остальных.

## Веса Двоичных Позиций

В одном octet позиции имеют следующие значения:

| Bit position | 8 | 7 | 6 | 5 | 4 | 3 | 2 | 1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Weight | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

Если двигаться справа налево, каждый следующий вес удваивается:

```text
1, 2, 4, 8, 16, 32, 64, 128
```

Это powers of two:

| Power | Value |
| --- | ---: |
| `2^0` | 1 |
| `2^1` | 2 |
| `2^2` | 4 |
| `2^3` | 8 |
| `2^4` | 16 |
| `2^5` | 32 |
| `2^6` | 64 |
| `2^7` | 128 |

При записи octet слева направо используется обратный порядок:

```text
128 64 32 16 8 4 2 1
```

## Модель С Фиксированными Контейнерами

Binary можно представить как восемь контейнеров фиксированного размера:

```text
[128] [64] [32] [16] [8] [4] [2] [1]
```

Для получения нужного decimal value выбираются подходящие контейнеры:

- `1` означает «использовать этот контейнер»;
- `0` означает «пропустить этот контейнер».

Например, число `20`:

```text
20 = 16 + 4
```

Флаги:

```text
Weights: 128 64 32 16  8  4  2  1
Bits:      0  0  0  1  0  1  0  0
```

Результат:

```text
20 = 00010100
```

## Алгоритм Decimal to Binary

Для числа от `0` до `255`:

1. Записать веса `128 64 32 16 8 4 2 1`.
2. Начать с веса `128`.
3. Проверить, помещается ли текущий вес в оставшееся число.
4. Если помещается, записать `1` и вычесть вес.
5. Если не помещается, записать `0`.
6. Перейти к следующему весу.
7. Продолжать до позиции со значением `1`.
8. Проверить результат обратным сложением.

Шаблон:

```text
Decimal value: N

Weight: 128 64 32 16 8 4 2 1
Bit:      ?  ?  ?  ? ? ? ? ?
```

## Пример 1: Decimal 153

Начальное значение:

```text
153
```

Проверяем каждый вес:

| Weight | Помещается? | Bit | Остаток |
| ---: | --- | ---: | ---: |
| 128 | Да | 1 | `153 - 128 = 25` |
| 64 | Нет | 0 | 25 |
| 32 | Нет | 0 | 25 |
| 16 | Да | 1 | `25 - 16 = 9` |
| 8 | Да | 1 | `9 - 8 = 1` |
| 4 | Нет | 0 | 1 |
| 2 | Нет | 0 | 1 |
| 1 | Да | 1 | `1 - 1 = 0` |

Получаем:

```text
Weights: 128 64 32 16 8 4 2 1
Bits:      1  0  0  1 1 0 0 1

153 = 10011001
```

Проверка:

```text
128 + 16 + 8 + 1 = 153
```

## Пример 2: Decimal 210

Разложение:

```text
210 = 128 + 64 + 16 + 2
```

Таблица:

```text
Weights: 128 64 32 16 8 4 2 1
Bits:      1  1  0  1 0 0 1 0
```

Результат:

```text
210 = 11010010
```

Проверка:

```text
128 + 64 + 16 + 2 = 210
```

## Пример 3: Decimal 20

Разложение:

```text
20 = 16 + 4
```

Таблица:

```text
Weights: 128 64 32 16 8 4 2 1
Bits:      0  0  0  1 0 1 0 0
```

Результат:

```text
20 = 00010100
```

Ведущие нули важны: `10100` математически представляет то же число, но `00010100` сразу показывает полный IPv4 octet.

## Пример 4: Decimal 192

```text
192 = 128 + 64
```

```text
Weights: 128 64 32 16 8 4 2 1
Bits:      1  1  0  0 0 0 0 0
```

```text
192 = 11000000
```

Это значение часто встречается в private IPv4 range `192.168.0.0/16`.

## Пример 5: Decimal 168

```text
168 = 128 + 32 + 8
```

```text
Weights: 128 64 32 16 8 4 2 1
Bits:      1  0  1  0 1 0 0 0
```

```text
168 = 10101000
```

Теперь первые два octets адреса `192.168.1.10` выглядят так:

```text
192 = 11000000
168 = 10101000
```

## Почему Максимум Равен 255

Если все 8 bits установлены в `1`, используются все веса:

```text
11111111
```

```text
128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255
```

Поэтому один IPv4 octet находится в диапазоне:

```text
00000000 = 0
11111111 = 255
```

Всего 8 bits могут представить:

```text
2^8 = 256 different values
```

Это значения от `0` до `255`, а не от `1` до `256`.

## Важные Пограничные Значения

| Decimal | Binary | Объяснение |
| ---: | --- | --- |
| 0 | `00000000` | Ни один вес не используется |
| 1 | `00000001` | Используется только вес 1 |
| 2 | `00000010` | Используется только вес 2 |
| 127 | `01111111` | Все веса кроме 128 |
| 128 | `10000000` | Используется только вес 128 |
| 254 | `11111110` | Все веса кроме 1 |
| 255 | `11111111` | Используются все веса |

Особенно полезно узнавать без расчёта:

```text
128 = 10000000
192 = 11000000
224 = 11100000
240 = 11110000
248 = 11111000
252 = 11111100
254 = 11111110
255 = 11111111
```

Эта последовательность позже появится в subnet masks.

## Обратная Проверка: Binary to Decimal

Чтобы проверить перевод, сложите веса позиций, в которых стоит `1`.

Пример:

```text
10110110
```

```text
Weights: 128 64 32 16 8 4 2 1
Bits:      1  0  1  1 0 1 1 0
```

Используются:

```text
128 + 32 + 16 + 4 + 2 = 182
```

Следовательно:

```text
10110110 = 182
```

Обратная проверка обнаруживает пропущенный bit или ошибочное вычитание.

## Быстрый Метод Через Сумму

Не обязательно физически вычитать на каждом шаге. После практики можно сразу подбирать сумму powers of two.

Например:

```text
100 = 64 + 32 + 4
```

```text
100 = 01100100
```

Или:

```text
200 = 128 + 64 + 8
```

```text
200 = 11001000
```

Метод вычитания надёжнее в начале. Метод суммы быстрее после того, как веса запомнились.

## Перевод Полного IPv4 Address

Возьмём:

```text
192.168.1.10
```

Переведём каждый octet:

| Decimal octet | Binary octet |
| ---: | --- |
| 192 | `11000000` |
| 168 | `10101000` |
| 1 | `00000001` |
| 10 | `00001010` |

Полная запись:

```text
11000000.10101000.00000001.00001010
```

Точки разделяют octets и не являются bits.

## Связь С Subnet Masks

Рассмотрим маску:

```text
255.255.255.0
```

В binary:

```text
11111111.11111111.11111111.00000000
```

Она соответствует prefix:

```text
/24
```

Первые 24 bits установлены в `1` и обозначают network portion. Последние 8 bits установлены в `0` и обозначают host portion.

Другой пример:

```text
255.255.255.192
```

Последний octet:

```text
192 = 11000000
```

Полная маска:

```text
11111111.11111111.11111111.11000000
```

Это prefix:

```text
/26
```

Binary показывает, почему decimal mask `192` добавляет два network bits.

## Почему В Subnet Mask Единицы Непрерывны

Обычная IPv4 subnet mask содержит непрерывную последовательность `1`, после которой идут только `0`:

```text
11111111.11111111.11110000.00000000
```

Такой pattern соответствует `/20`.

Значение octet с переходом от network bits к host bits может быть только одним из:

| Binary | Decimal |
| --- | ---: |
| `00000000` | 0 |
| `10000000` | 128 |
| `11000000` | 192 |
| `11100000` | 224 |
| `11110000` | 240 |
| `11111000` | 248 |
| `11111100` | 252 |
| `11111110` | 254 |
| `11111111` | 255 |

Значение вроде `10101000` является корректным binary octet, но не корректным переходным octet обычной contiguous subnet mask, потому что единицы разорваны нулями.

## Практический Подход

Для обучения:

1. Выполните 10-15 conversions вручную.
2. Всегда записывайте таблицу весов.
3. Сохраняйте все 8 bits.
4. Проверяйте результат обратным сложением.
5. После ручной попытки используйте calculator для проверки.
6. Повторяйте значения subnet mask до мгновенного узнавания.

В production использование calculator, spreadsheet или IPAM не является ошибкой. Инженерные инструменты уменьшают риск случайной арифметической ошибки. Однако ручной навык нужен, чтобы понимать результат, быстро замечать невозможные значения и работать на экзамене или при troubleshooting без зависимости от конкретного инструмента.

## Частые Ошибки

### Записывать Меньше Восьми Bits

```text
20 = 10100
```

Математически это верно, но для IPv4 лучше:

```text
20 = 00010100
```

### Менять Порядок Весов

Правильный порядок слева направо:

```text
128 64 32 16 8 4 2 1
```

### Забывать Вычесть Использованный Вес

После записи `1` соответствующее значение должно быть вычтено из остатка.

### Считать 256 Допустимым Octet

Один octet имеет 256 возможных состояний, но максимальное значение равно `255`, поскольку отсчёт начинается с `0`.

### Путать Bit Position и Weight

Восьмая позиция слева имеет вес `128`, а не `8`.

### Проверять Только По Внешнему Виду

Binary pattern может выглядеть правдоподобно и всё равно быть неправильным. Сложите активные веса.

### Считать Любое Binary Значение Корректной Subnet Mask

Любой octet от `00000000` до `11111111` допустим как число, но обычная subnet mask требует непрерывных единиц.

## Контрольные Вопросы

### Вопрос 1

Какие веса имеют bits одного IPv4 octet?

Ответ:

```text
128, 64, 32, 16, 8, 4, 2, 1
```

### Вопрос 2

Почему значение octet не может быть больше `255`?

Ответ:

```text
В octet только 8 bits. Максимум получается при всех единицах:
128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255.
```

### Вопрос 3

Как записать `153` в binary?

Ответ:

```text
153 = 128 + 16 + 8 + 1 = 10011001
```

### Вопрос 4

Почему `20` следует записывать как `00010100`, а не просто `10100`?

Ответ:

```text
Полная восьмибитная запись явно показывает границы IPv4 octet.
```

### Вопрос 5

Как проверить binary value `11010010`?

Ответ:

```text
128 + 64 + 16 + 2 = 210
```

### Вопрос 6

Как decimal octet `192` выглядит в binary и почему он важен?

Ответ:

```text
192 = 11000000. В subnet mask это означает два network bits
в данном octet.
```

## Команды и Термины

| Термин | Значение |
| --- | --- |
| Bit | Одна binary digit: `0` или `1`. |

| Octet | Группа из 8 bits в IPv4 notation. |
| Decimal | Система счисления с основанием 10. |
| Binary | Система счисления с основанием 2. |
| Bit weight | Decimal value, принадлежащее позиции bit. |
| Leading zero | Ноль слева, сохраняющий полную ширину octet. |
| Dotted decimal | Обычная запись IPv4 четырьмя decimal octets. |

| Host portion | Bits, идентифицирующие interface внутри network. |
