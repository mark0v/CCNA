# Pairwise Testing

## Summary

Попарное тестирование, или Pairwise Testing, - это техника формирования тестовых данных, которая помогает сильно сократить количество test cases, но при этом сохранить хорошее покрытие комбинаций.

Идея простая: вместо проверки всех возможных комбинаций параметров мы проверяем все возможные пары значений параметров.

Большинство дефектов часто возникает из-за взаимодействия одного или двух факторов. Поэтому проверка всех пар значений помогает найти много ошибок без взрыва количества тестов.

## Main Goals

Основные цели pairwise testing:

- убрать избыточные проверки;
- обеспечить качественное покрытие параметров;
- найти максимум дефектов на минимальном наборе тестов;
- заменить полный перебор более разумным набором комбинаций.

Pairwise Testing особенно полезно там, где у системы много входных параметров: браузер, ОС, язык, роль пользователя, тип устройства, настройки, варианты оплаты, типы данных и так далее.

## Example 1: Simple Logic

Представим, что есть три параметра: `A`, `B` и `C`.

Каждый параметр может принимать два значения:

- `Yes`;
- `No`.

Если проверять все комбинации, получится:

```text
2 x 2 x 2 = 8 test cases
```

При pairwise подходе может быть достаточно 4 комбинаций, потому что в них уже будут покрыты все пары:

- `A + B`;
- `A + C`;
- `B + C`.

Мы не проверяем каждую полную комбинацию, но проверяем каждое парное взаимодействие значений.

## Example 2: Tax Calculation

Допустим, нужно протестировать систему расчета налогов.

Есть такие параметры:

| Parameter | Values |
| --- | --- |
| Gender | male, female |
| Age | under 25, 25-60, over 60 |
| Children | yes, no |

Полный перебор:

```text
2 x 3 x 2 = 12 test cases
```

Pairwise Testing может сократить набор примерно до 6 test cases, где каждая уникальная пара встретится хотя бы один раз.

Примеры пар:

- `male + under 25`;
- `female + children`;
- `25-60 + no children`;
- `over 60 + female`.

Такой подход уменьшает объем тестирования, но не оставляет парные взаимодействия без внимания.

## Example 3: Website Configuration

Представим, что веб-сайт должен работать в разных окружениях.

Параметры:

| Parameter | Values |
| --- | --- |
| Browser | Opera, Firefox |
| OS | Windows, Linux |
| Language | UA, EN |
| Database | MySQL, Oracle, MSSQL |

Полный перебор:

```text
2 x 2 x 2 x 3 = 24 configurations
```

Pairwise Testing может сократить это количество примерно до 6-7 конфигураций.

Это особенно полезно для compatibility testing, когда полный перебор всех платформ, браузеров, языков и настроек становится слишком дорогим.

## Example 4: Font Settings Window

В текстовом редакторе окно `Font` может иметь много параметров:

- font type;
- font style;
- font size;
- color;
- underline;
- дополнительные flags: `Strikethrough`, `Shadow` и другие.

Если параметров много, полный перебор может дать сотни тысяч вариантов.

Например:

```text
442368 combinations
```

Pairwise Testing позволяет сократить этот огромный набор до нескольких десятков тестов и при этом сохранить уверенность, что основные парные взаимодействия параметров проверены.

## Tools

Составлять pairwise-комбинации вручную сложно, особенно когда параметров много.

Для автоматизации можно использовать специальные инструменты, например `PICT` от Microsoft.

PICT принимает на вход текстовый файл с параметрами и значениями, а затем генерирует готовый набор тестовых сценариев.

Например, если полный перебор дает 4704 комбинации, pairwise-инструмент может сократить набор примерно до 60 test cases.

## When To Use Pairwise Testing

Pairwise Testing хорошо применять:

- когда у функциональности много входных параметров;
- когда полный перебор комбинаций невозможен или слишком дорог;
- на стабильном функционале;
- на поздних этапах разработки;
- когда текущие тесты перестали находить новые дефекты;
- для configuration и compatibility testing.

Перед использованием pairwise testing важно убедиться, что базовые сценарии уже проходят.

Например, сначала стоит выполнить Smoke Testing. Если базовая функциональность сломана, pairwise-тесты могут стать шумными: один test case будет включать много нестандартных параметров, и будет сложнее понять, что именно вызвало сбой.

## Key Idea

Pairwise Testing не заменяет все остальные test design techniques.

Это способ разумно сократить количество комбинаций, когда exhaustive testing невозможен.

Главная мысль:

> We do not test everything. We test the most valuable combinations.
